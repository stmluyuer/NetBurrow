# 架构、实现来源与验证边界

NetBurrow 为少量朋友组队转发《以撒的结合：忏悔+》的游戏数据。Windows 客户端、32 位游戏接入组件和 Relay 分工如下；使用、构建及打包入口见 [README](../README.md)，版本变化见 [更新日志](../CHANGELOG.md)。

## 组件与数据路径

| 组件 | 职责 |
| --- | --- |
| `netburrow-app` | x64 桌面界面、设置、托盘、更新检查和诊断包导出 |
| `netburrow-core` | 配置与组码、连接管理、游戏进程监视、本地 IPC、Relay 通信与状态诊断 |
| `netburrow-injector` | x86 注入 helper，核对目标进程并加载 Hook DLL |
| `netburrow-hook` | x86 DLL，接入游戏的 Steam 网络接口，以有界队列衔接游戏线程和 IPC |
| `netburrow-protocol` | 自有消息、编码、握手能力和可靠重放记录 |
| `netburrow-relay` | 组白名单、成员管理、TCP/UDP 转发、队列预算及会话恢复 |

主要数据路径是：游戏 Steam 网络接口 → Hook 队列 → 本机 IPC → 客户端 → Relay → 队友客户端 → 队友 IPC 与 Hook → 队友游戏。游戏调用不等待公网响应；客户端和 Relay 不修改游戏数据载荷。

本地 IPC 使用回环 TCP 和每次启用生成的实例身份。客户端、游戏实例和连接代次共同限定数据所属会话；旧连接或旧游戏的数据不能进入新实例。进入 Relay 的组码须预先由管理员加入白名单，本机新建组码不会自动取得服务器授权。

## Hook 与恢复边界

当前 Hook 拦截接口创建和 Steam 回调，只接管收发并观察原生会话状态；会话接受、关闭和状态返回仍由 Steam 处理。数据收发统一使用 NetBurrow 通路，不能把同一数据流在 NetBurrow 与 Steam 之间任意切换。回调后检查并补装被还原的已登记入口；无法安全接入时明确停止。

队列同时限制包数和字节数。可靠容量超限会隔离受影响成员并报告失败；可靠记录的确认表示下一传输阶段接纳，不代表游戏已经读取。原会话恢复保留有界重放记录；获准重新加入时清除旧会话记录，避免重复投递。公网通路恢复也不保证游戏自身恢复同步。

关闭联机和进程退出应停止工作线程、结束采集并释放本次会话资源。部分 Hook 原函数登记按游戏进程生命周期保留；单次内存占用偏高或工作集未立即下降，不足以判定内存泄漏。实际增长问题需要同一进程内的可比重复操作与持有关系证据。

游戏接入行为参考 [TractorBeam 固定版本 ea0393f](https://github.com/mcthesw/TractorBeam/tree/ea0393f5665dd1e0775d9dc1d0c987304461191c)，该上游版本使用 [AGPL-3.0](https://github.com/mcthesw/TractorBeam/blob/ea0393f5665dd1e0775d9dc1d0c987304461191c/LICENSE)。项目原始独立实现要求不将其源码、协议库、二进制、界面或资产作为工程底座；当前构建不依赖研究目录。当前 Hook 的队列、接口登记及安装检查使用 NetBurrow 的实现。

这些设计要求与结构差异不是对全部代码来源的法律审计结论。后续引入外部实现、片段或资产时，必须记录具体来源和适用许可；NetBurrow 自有代码的 [MIT 声明](../LICENSE) 不覆盖上游的独立许可要求。通用依赖、内置字体及资源的通知见 [第三方许可清单](../THIRD_PARTY_LICENSES.txt)。图标的生成入口为 `scripts/generate-icons.ps1`，系统字体在运行时从 Windows 本机读取，不随包复制。

## 本地化与诊断

界面和面向用户的诊断文字使用同处定义的 `text!` / `text_format!` 双语宏。语言设置在重启后生效，技术日志与协议字段保留原标识。启动时从 Windows 实际系统目录读取字体，中文字体均不可用时仅本次运行改用英文，保留保存的语言偏好。

普通诊断导出只读取有限长度的状态和日志，不复制设置文件，并清除组码、疑似凭据、长标识符及包含本机路径的日志行。完整闪退转储是另行确认的功能，可能含游戏内存中的个人信息；使用方式与边界见 [闪退采集说明](crash-capture.md)。诊断文件保存在本机，不会自动上传。

## 验证与分发

协议、身份与组隔离、可靠收发、断线恢复、队列溢出和诊断脱敏使用对应的定向测试。界面文案和样式使用编译检查与真实渲染预览；不因这类改动默认执行 x86 注入测试。

公开源码应包含许可证、第三方清单、构建入口和锁文件。客户端包和 Relay 源码包都携带许可文件；发布页应注明最终源码提交及客户端版本。不要将本机配置、日志、工具链缓存或研究材料加入发行包。

本地构建、离线预览及测试通过只能证明所覆盖的路径。真实多人对局、长时间内存变化、实际断网恢复、非默认 Windows 安装环境和 Linux Relay 部署仍需分别验证。尚未完成的场景应保留实验性表述，不用“已修复闪退”或“稳定联机”等结论替代实测。
