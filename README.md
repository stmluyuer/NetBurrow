# NetBurrow

NetBurrow 是给《以撒的结合：忏悔+》朋友联机使用的 Windows 工具。它把已启用的游戏 P2P 数据定向转发到同组成员；Relay 只保留在线连接和当前游戏实例，不保存房间历史。

## 使用前准备

先让服务器端 AI 按 [服务器部署说明](docs/server-ai-handoff.md) 构建并启动 Relay。客户端填写的服务器格式是 `主机名或IP:端口`，默认端口为 `24872`，TCP 和 UDP 使用同一个端口。

解压 `NetBurrow-<版本>-win-x64.zip` 到固定目录，不要单独移动其中的 `NetBurrow.exe`、`netburrow-injector.exe` 或 `netburrow_hook.dll`。首次运行时会在 `%LOCALAPPDATA%\NetBurrow\settings.json` 保存本机设置；压缩包不会包含该文件。

## 连接步骤

“启用联机”会先在后台自检配置、32 位游戏与工具文件，再用现有协议短暂连接 Relay 检查握手与成员状态支持；通过后才启用。也可单独点击“启用前自检”。自检不启动游戏或加载 Hook；游戏文件版本会显示，但没有版本白名单，兼容性仍需实际接入确认。检查期间修改连接设置后需重新检查。

1. 打开 `NetBurrow.exe`，填写 Relay 地址。在“游戏与传输设置”中确认游戏路径是实际的 `isaac-ng.exe`。
2. 点击“创建联机组”创建 `NB1-` 开头的组码，私下发给同一局的朋友；朋友在自己的工具中粘贴同一个组码。
3. 默认选择 TCP。两端和 Relay 都确认可用后，可改为“UDP 优先”：不可靠游戏包走 UDP，可靠包仍走 TCP。
4. 点击“启用联机”，状态显示“Relay 已连接，请从 Steam 正常启动游戏”后，从 Steam 正常启动游戏并使用原有邀请、开局流程。

启动游戏前工具可以长期等待。游戏关闭后会回到等待状态；重新启动游戏会使用新的实例代号。默认关闭窗口会退出工具并停止联机；开启“关闭窗口时最小化”后，关闭窗口会正常最小化到任务栏，联机继续。该选项切换后自动保存，不会保存尚未确认的连接设置；保存失败会恢复原值。托盘可显示窗口、停止联机或退出。重复启动工具会唤回现有窗口。

连接异常会显示对应处理步骤，并提供“查看排查日志”入口；服务器不可达、连接超时、满员、拒绝加入和协议不匹配分别提示。游戏接入失败会提示检查文件或版本并重开游戏。同组看不到朋友时，请核对双方服务器地址和完整组码；不同的有效组码会进入不同联机组。

- 连接设置会标记“未保存”和“尚未应用”；联机期间可展开查看本次实际使用的配置，保存新设置不会改变当前会话。
- “最近使用的连接”保留最多 5 条服务器与联机组记录，仅存本机。选择记录只填入表单；移除记录不影响当前填写或正在使用的连接。
- 联机质量反映到 Relay 的延迟与心跳：延迟 ≥150 ms、最近 20 个样本极差 ≥80 ms，或最近 60 秒发生断线时提示波动；延迟 ≥300 ms 或 5 秒未收到心跳提示异常。它不是玩家间延迟或丢包率，也不影响现有发送频率和联机协议。
- “启动设置”中的开机启动与启动后最小化独立控制，默认均关闭。开机启动只在用户打开开关时设置当前账户的 Windows 登录启动项，不会自动启用联机；移动工具后需重新开关一次更新路径。

- “导出诊断”生成本机 UTF-8 文本文件，包含版本、状态、计数和每份日志末尾最多 128 KiB；隐藏组码、长标识符及已知显示名等内容，省略疑似凭据和包含本机路径的日志行。文件位于 `%LOCALAPPDATA%\NetBurrow\diagnostics`，可在界面定位，不会自动上传。
- 正常退出时记住窗口位置、大小和最大化状态，下次启动恢复；最小化退出后仍以正常或最大化窗口打开。原显示器移除导致位置完全离屏时，由 Windows 调整到可见位置。
- “关于”显示当前版本，提供项目主页、问题反馈和发布页入口；检查更新通过浏览器打开发布页，由用户手动下载。
- “重要状态通知”默认开启，切换后自动保存。接入成功、连接中断或接入失败时发出静音托盘通知，点击通知可打开工具；成功和异常通知各自 30 秒内不重复，关闭通知不会在重新开启后补发旧状态。通知显示仍由 Windows 通知设置控制。

如果游戏已经启动，可在“游戏与传输设置”勾选“允许中途 Hook（实验性）”，然后点击“启用联机”。该设置默认关闭，会随配置保存；启用联机期间不能修改。请仅在主菜单、尚未联机时使用：工具不能识别主菜单或阻止对局中接入，已有回调也可能无法接管。失败或断线后仍须重启游戏，不能靠反复启用工具恢复当前进程。

## 同组成员状态

启用联机后，状态卡会显示同组所有成员的显示名、游戏状态、到 Relay 的延迟、实际 TCP/UDP 状态和累计收发包数。可在“游戏与传输设置”填写可选显示名，最多 24 个字符；不填写则显示成员编号。

延迟是各成员自行测得的“该成员 ↔ Relay”往返时间，不是玩家之间的端到端延迟。状态约每 3 秒上报一次；超过 10 秒未更新会标记过期并隐藏旧统计。数据只在当前组内共享，未上报的成员显示“待上报”。

使用本次成员状态功能前，先按 [服务器部署说明](docs/server-ai-handoff.md) 从 GitHub 的指定分支和固定 commit 更新 Relay，再让所有朋友更新客户端。新版客户端连接不支持状态同步的旧 Relay 时，会在接入游戏前提示更新服务器。新版 Relay 仍接受旧客户端，但旧客户端不能上报或查看这些统计。服务器更新会断开当前连接，请在一局结束后操作，并重启游戏再开始新局。

## 注意事项

- 本版只接受 32 位的 `isaac-ng.exe`；默认只接入启用工具后启动的游戏，允许中途 Hook 后也会尝试接入已运行的唯一匹配进程。
- 组码相当于当前 Relay 的组凭据，不要公开发布或发给不在本局的人。它不是 Steam 账号认证，也没有 TLS 加密。
- 停止联机、Relay 断线或工具异常退出后，请完全退出并重启 `isaac-ng.exe`，再开始新的对局；本版不恢复旧局，也不承诺热卸载 Hook DLL。
- 本次尚未完成 Linux 实机构建或两台机器的真实游戏对局验证。客户端启动检查通过；本次成员列表截图为黑屏，实际布局和托盘人工操作仍需确认。
- 当前仅在原生宿主验证了 Hook 接入后注册游戏回调的路径。若游戏在 Hook 接入前已注册回调，请求可能无法补发，需在实机联机时确认。

## 日志排查

点击“查看日志 → 打开日志文件夹”，或直接打开 `%LOCALAPPDATA%\NetBurrow\logs`。

- `client.log`：带时间的连接状态、进程识别、helper 退出结果、IPC、成员数量、断线原因；每 10 秒记录收发和延迟统计。
- `injector.log`：目标检查、DLL 加载及初始化返回码（返回 2 表示该进程已初始化过，需重开游戏）。
- `hook.log`：Steam 接口、回调入口、IPC 初始化/异常及捕获到的回调数量。数量为 0 可能表示回调在注入前已经注册，不代表确定故障。

每份日志上限 2 MB，滚动保留一份同名前缀的 `.previous.log`。日志不包含组码、token、SteamID 或游戏包内容；关掉工具后仍会保留。排障时发送这三个日志及存在的 previous 文件即可，不要发送 `settings.json`。日志写入失败会显示在日志窗口中；旧版本运行期间的记录无法补回。

Relay 的 stderr 由服务器上的 systemd journal 收集。它只记录生命周期事件，以及每 10 秒一次的在线数、已绑定游戏数、TCP/UDP 投递数、拒绝数和队列字节等累计汇总；不会逐包记录，也不会写入组码、token、显示名、SteamID、IP 或 payload。查看、导出和保留策略核查命令见 [服务器部署说明](docs/server-ai-handoff.md)；不要为排障擅自调整全局 `journald` 配置。

成员退出或重开游戏时，Relay 会丢弃仍发往旧目标的 TCP/UDP 数据，避免发送方因残留包而退出联机。汇总中的 `target_unavailable` 表示同组目标当前不可用，`target_epoch_expired` 表示目标游戏实例已改变；发送方身份或实例不匹配仍记录为 `packet source or epoch is invalid` 并拒绝。此修复需要更新 Relay 才会生效，仅更新客户端不能修复旧 Relay 的连带断线；它也不保证游戏在房主退出后能够继续当前对局。

## 开发者打包

日常只打包客户端：右键仓库根目录的 `打包客户端.ps1`，选择“使用 PowerShell 运行”。脚本自动构建 x64 客户端与 32 位注入器/DLL、整理许可证并生成 `.local\dist\NetBurrow-<版本>-win-x64.zip`；成功后打开产物目录，窗口会保留结果，按回车关闭。默认每次打包将根 Cargo.toml 的修订号加 1（例如 0.1.0 → 0.1.1），同步 Cargo.lock，保留其他版本的 ZIP。

如果系统阻止右键运行，可在仓库根目录执行以下命令（仅对本次进程放行脚本）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\打包客户端.ps1
```

自动化调用可添加 `-NonInteractive`，关闭等待回车和打开目录；成功返回退出码 0，失败返回 1。脚本依赖本仓库已准备好的 `.local` Rust 工具链、离线依赖及 MSVC 构建环境，不会自动安装环境。

版本只在准备分发时递增，普通编辑或 `cargo build` 不改版本。修复和界面小调整递增修订号；新增完整功能时指定次版本（例如 `0.2.0`）；准备正式发布时指定 `1.0.0`。界面、诊断报告、启动日志及 Relay 源码包统一读取根配置版本。

```powershell
# 新功能：指定版本（不能低于当前版本）
.\打包客户端.ps1 -Version 0.2.0
# 重复打包或失败后重试：保留当前版本
.\打包客户端.ps1 -KeepVersion
```

失败后已递增的版本会保留，使用 `-KeepVersion` 重试可避免再次递增。保留版本会替换该版本的 ZIP，仅用于未发布的包；已经发给别人的内容有变化时，应使用新版本。

需要同时生成客户端包与 Relay 源码包时，在仓库根目录运行（同样支持 `-Version` 和 `-KeepVersion`）：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\package.ps1
```

脚本使用仓库 `.local` 中的 Rust 1.97 工具链，离线构建 x64 桌面程序与 i686 helper/DLL，输出到 `.local\dist`：

- `NetBurrow-<版本>-win-x64.zip`
- `NetBurrow-<版本>-relay-source.zip`

`scripts\package.ps1 -SkipBuild` 仅重新压缩已记录的构建产物，自动保留版本；版本或二进制文件与记录不符时会拒绝打包，需改用 `-KeepVersion` 重建。首次使用必须正常构建一次。

打包脚本还会为两个 ZIP 各自生成第三方依赖许可证说明和可用的许可证文件副本。它不部署 Relay、不访问 VPS，也不包含 `.local`、研究资料、日志或真实配置。
